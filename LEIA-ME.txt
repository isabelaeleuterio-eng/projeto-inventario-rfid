CORREÇÃO DO FLUXO RFID — ARQUIVOS PREPARADOS

Arquivos incluídos:
- server.js: backend atualizado para reconhecer a tag pessoal antes da retirada/devolução.
- index.html: interface de operação autocontida e responsiva.
- package.json / package-lock.json: dependências originais.

FLUXO PREVISTO
Retirada: tag pessoal -> selecionar equipamento no site -> tag do equipamento -> grava empréstimo e solicita abertura.
Devolução: tag pessoal -> sistema mostra equipamento aberto dessa pessoa -> tag do equipamento correto -> solicita abertura -> mesma tag pessoal novamente -> grava devolução.

ATENÇÃO ANTES DE PUBLICAR
1. Estes arquivos ainda não foram testados contra o ESP32 físico nem contra o ambiente de produção.
2. O comando de abertura é sinalizado no evento RFID com abrir:true. Confirme no firmware que ele consulta /api/status e executa a abertura apenas uma vez por evento novo. O firmware completo não foi incluído neste pacote.
3. O fluxo fica em memória do servidor; reiniciar o serviço durante uma operação pode exigir começar de novo.
4. Faça backup dos arquivos atuais antes de substituir. Não execute SQL: esta alteração não exige migração.
5. Não inclua .env, chaves Supabase ou senhas no GitHub. Se uma chave secreta já foi exposta, revogue-a e atualize as variáveis do Render.

Para publicar, copie os arquivos para os caminhos correspondentes do repositório mantendo a estrutura esperada pelo projeto. Este index.html substitui a página de operação, mas deve ser colocado no diretório servido pelo servidor (SITE/index.html, conforme SITE_DIR no server.js).
